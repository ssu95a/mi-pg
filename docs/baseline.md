# Документ описывает правила оформления, именования и версионирования объектов БД при первоначальном формировании поставки MI.

Baseline объектов MI

## 1. Версия

Все объекты первоначальной загрузки считаются версией:

`1.0.1`

Это стартовая версия объектов в новом репозитории `mi-pg`.

## 2. Имена файлов

Имя SQL-файла совпадает с именем объекта в БД.

Примеры:

```text
mi_req.sql
mi_rsp.sql
mi_person.sql
mi_log.sql
v_mi_0001.sql
```

Дополнительные префиксы и служебные обозначения для baseline не используются.

## 3. Кодировка

Все исходные SQL-файлы в Git хранятся в:

`UTF-8`

Windows-1251 используется только при подготовке поставочных файлов для update, если этого требует существующий механизм поставки.

## 4. Заголовки SQL

Для baseline специальные служебные заголовки в SQL-файлы не добавляются.

То есть не требуется:

```sql
-- jira:
-- version:
-- operation:
-- object:
```

Версия и назначение объекта фиксируются PostgreSQL-комментарием к объекту.

## 5. Комментарий объекта

Комментарий строится по формату:

`<Подсистема>. <Модуль>. <Описание объекта>. '$id: {<версия>} {<дата>} <пользователь>$'`

Для baseline:

`<версия> = 1.0.1`

Пример для таблицы `xxi.mi_req`:

```text
MI-edo. Общий реестр запросов. Таблица единого реестра. '$id: {1.0.1} {05.10.2026} Sulimoff$'
```

## 6. Пример SQL-файла таблицы

Файл:

`mi_req.sql`

```sql
create table if not exists xxi.mi_req
(
    ...
);

comment on table mi.mi_req is
$$MI-edo.. Реестр запросов. Таблица единого реестра. '$id: {1.0.1} {05.10.2026} Sulimoff$'$$;
```

Dollar quoting `$$...$$` используется для комментария, чтобы внутренние одинарные кавычки вокруг `$id` не приходилось экранировать.

## 7. Структура baseline

Пример:

```text
ddl/
└── mi_request/
    ├── tables/
    │   ├── mi_req.sql
    │   ├── mi_rsp.sql
    │   └── mi_req_event.sql
    │
    ├── sequences/
    │   ├── s_mi_req.sql
    │   └── s_mi_rsp.sql
    │
    ├── packages/
    │   └── MI_request_Api.sql
    │
    └── triggers/
        └── tad_mi_req.sql
```

Baseline представляет актуальное исходное состояние объектов БД.

История изменений через Jira, отдельные operation-скрипты и новые версии объектов начинается после фиксации baseline.
